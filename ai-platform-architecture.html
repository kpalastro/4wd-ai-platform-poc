Reference architecture · Retail AI platform

One AI platform behind three channels

Ecommerce, in-store point of sale and call-centre voice are three products. They are not three AI stacks. This is the platform that serves all three, taken apart layer by layer, with the build-or-buy call made explicit at every step.

Written against the brief for an AI-first platform engineer at a multi-channel Australian adventure retailer: a Shopify replatform, a bespoke AI-first POS, and AI voice agents for the call centre. Grounded in a read of the retailer's public storefront, store directory, returns policy and support portal, so the integration inventory describes systems that actually exist rather than ones that might. Component names are generic; the decisions are not.

Thesis

Why a platform, and not three projects

Run the Shopify replatform, the POS build and the voice agents as three separate projects and they will each grow their own model integration, prompt store, tool layer, evaluation suite and audit trail. Build a capability three times and every change costs three times as much. Worse, every governance question gets three different answers, and none of them is defensible to an auditor.

The platform costs more in month one and far less by month nine. What makes it work is being strict about which capabilities are genuinely shared and which are genuinely channel-specific. Almost every failed "AI platform" is a shared layer that swallowed something it had no business owning.

What is genuinely shared

Model access, routing and cost control. Tool access to systems of record, which is the expensive part. Retrieval over product, fitment and policy knowledge. Session and customer memory. Guardrails, PII handling and audit. Evaluation, tracing and release gates. Prompt and agent versioning.

What is genuinely channel-specific

The transport: HTTP and server-sent events at one end, streaming audio at the other. The turn-taking model, because a caller expects an answer in under a second and a storefront shopper does not. The interaction contract, since a voice agent must say it is an AI and a staff copilot must not pretend to be the manager. And the fallback path, because a lost WAN link means something very different in a Campbelltown store than in a browser tab.

  • RULE 1The channel owns interaction.Turn-taking, transport, disclosure and the degraded path live in the channel adapter, and nowhere else.
  • RULE 2The platform owns intelligence.Models, tools, retrieval, memory, guardrails and evals are shared services with their own owners, versions and SLAs.
  • RULE 3The systems of record own truth.The agent never becomes the source of a price, a stock level or a fitment. It reads them, cites them, and writes back through a governed path.

The tellWhen a component starts making decisions in two planes at once, it is a bug. A prompt that formats a phone number for a voice agent has crossed into the channel. A policy rule hard-coded in the POS adapter has crossed out of governance.

Architecture

Seven planes

Read the stack from the bottom up. Systems of record hold the truth. Plane 3 reaches into them through a governed tool mesh. Plane 4 assembles the context an answer needs. Plane 5 supplies the intelligence for one turn. Plane 6 turns that into a multi-step task with memory, guardrails and an escape hatch. Plane 7 speaks to a human in whatever medium they arrived in. Plane 1 runs down the side, because privacy, security, evaluation and audit are not a layer you pass through, they are constraints on every call in every other plane.

Requests flow up. Actions flow down. Every hop between planes crosses a versioned contract.

Component inventory

What each plane is made of

Each entry carries a build-or-buy call. The reasoning behind the calls is set out in Build or buy; the short version is that commodity intelligence gets bought, connective tissue and domain knowledge get built.

P7 · Channels

Thin adapters. Each one owns transport, turn-taking and the degraded path, and nothing else. Target: under 1,500 lines each.

Storefront assistantadopt + extend

Shopify theme app extension against the Storefront API. Falls back to native search when the agent is unavailable.

In-store POS copilotbuild

Staff-facing surface inside the bespoke POS. Runs against a local inference path so it survives a WAN outage.

Voice agentbuild

Telephony leg, streaming speech, barge-in, disclosure. The tightest latency budget in the system.

Staff copilotbuild

Internal surface in Slack or Teams. Doubles as the lowest-risk proving ground for the whole platform.

Agent ops consolebuild

Escalation queue, transcript replay, live containment and cost, per-agent kill switch. Non-negotiable from day one.

P6 · Agent & orchestration

The plane that turns a single model call into a task with memory, limits and an escape hatch.

Session servicebuild

Channel-agnostic conversation state. A call, a chat and a POS session all resolve to one thread id, so context survives a handoff.

Intent routerbuy

Fast model classifies the turn and decides: cached answer, direct response, tool call, or straight to a human. The main latency and cost lever.

Agent runtimebuy

Tool-calling loop with hard budgets: maximum tool calls, tokens and wall-clock per turn. Frameworks are commodity; budget enforcement is not.

Guardrail enginebuild

Input filters for injection and off-domain asks, output filters for groundedness, tone and invented values, and PII redaction on both sides.

Escalation & handoffbuild

Triggers on low confidence, sentiment, explicit request, complaint, legal or safety. Hands over a generated summary, not a cold transfer.

Agent & prompt registrybuild

Agents, prompts and tool bindings as versioned git artefacts with an owner, a changelog and a recorded eval score.

P5 · Model

One interface to every model, so no channel ever calls a provider SDK directly.

Model gatewaybuild

Policy-based routing on task, latency, cost and data class. Handles fallback, retries, caching, rate limits and per-cost-centre token accounting.

Frontier modelbuy

Reserved for hard turns: ambiguous fitment, multi-step policy reasoning, complaint handling. Routed to an Australian region when the payload carries personal data.

Fast modelbuy

Routing, classification, extraction, summarisation. Carries most traffic at a fraction of the cost and a third of the latency.

Speech stackbuy

Streaming STT with partial hypotheses and streaming TTS optimised for first-byte time. Behind an abstraction, because this market moves fastest.

Embeddings & rerankerbuy

Embedding model for the corpus index plus a cross-encoder reranker. Retrieval quality is mostly reranking, not embedding choice.

P4 · Context & data

Where a generic assistant becomes this retailer's assistant. Most of the raw material already exists in some form; almost none of it exists in a shape an agent can use.

Retrieval servicebuild

Hybrid lexical and vector search, metadata filters, rerank, and citation capture so every claim traces to a source document.

Knowledge corpusbuild

Roughly 87 articles are already published across Tips & Techniques, Complete Guides and DIY Projects, plus policy, freight and store operations material. It needs intent classification before it is usable, because destination content such as "Best Camping Spots Near Dandenong" is marketing rather than support and must never surface in a service answer.

Vehicle configuration modelbuild

Not a fitment matrix. The catalogue is universal-fit and named by dimension, so the asset is a model of the customer's vehicle and build: tub length and configuration, canopy or hard lid, roof load rating, existing 12V capacity, mounting interfaces. The hardest and most defensible thing in this architecture.

Policy rules enginebuild

Returns and warranty are rules, not prose: 30 days, store credit only, authorisation before return, exclusions for clearance and Scratch & Dent. Stored as date-versioned rules, because the published policy amends without notice and an agent quoting a superseded version is worse than one that defers.

Customer 360build

Identity resolution across POS, ecommerce, loyalty and CRM, so a caller is recognised whichever door they came through, with their wholesale tier and purchase channel attached.

Ingestion pipelinebuild

Connectors, change detection, freshness SLAs, ACL propagation, and a classification pass that tags every document by intent before it reaches an index.

P3 · Integration

Covered in full in the next section. This plane is where most AI programmes quietly fail.

MCP server fleetbuild

One typed server per system of record. The contract between agents and the business.

Event backbonebuy

Order placed, stock moved, call started, cart abandoned. Feeds proactive behaviour and keeps context warm.

API gateway & authbuy

One service identity per agent, scoped tokens, quotas and rate limits. No agent holds a human's credentials.

Write-safety layerbuild

Every agent-initiated write is idempotent, staged for human approval, or compensable. Read first, propose second, commit third.

CDC & webhooksbuild

Change data capture from systems of record so the context plane is minutes stale at worst, not overnight.

iPaaS connectorbuy

For long-tail internal systems that do not justify a bespoke server. A holding pen, not a destination.

P2 · Platform engineering

How the team ships, and the plane that makes AI changes safe to release on a Tuesday afternoon.

IaC & CI/CDbuild

Terraform for infrastructure, ephemeral preview environments per branch, standard pipelines for services and prompts alike.

Eval harnessbuild

Golden datasets per agent, scored automatically on every pull request. A prompt cannot reach production without a passing eval delta.

Tracing & costbuy

Distributed traces across speech, router, tools, model and output, with token and dollar cost attributed per channel and per conversation.

Prompt registrybuild

Prompts as versioned artefacts with rollback, so a prompt change is a deployable unit with an audit trail rather than a dashboard edit.

Flags & rolloutbuy

Shadow mode lets a new agent listen alongside the live one before it is allowed to speak. Canary by store, by queue, by percentage.

Secrets & KMSbuy

Managed keys, egress allowlists, and a network boundary that makes the model gateway the only path out.

Plane 3

The integration plane is the product

AI programmes rarely fail on models. They fail on plumbing. The model is a weekend's work; getting a governed, typed, auditable read and write into a fifteen-year-old ERP is a quarter.

So the integration plane gets treated as the platform's main deliverable. Every system of record exposes a Model Context Protocol server: a small, typed, versioned surface that declares exactly which operations an agent may perform, with what arguments, under which credential. Agents never speak REST. They never hold a database credential. They call tools.

The payoff is that integration becomes a reusable asset instead of glue buried in a prompt. A new agent gets the whole business on day one. A security review covers one surface rather than nine. And when the ERP is replaced, one server changes and no agent knows.

The gap the site revealsStore-level stock is not exposed anywhere. Today the only way to find out whether a Campbelltown store has an item is to phone 1800 88 39 64 and ask, and Click & Collect is arranged on that same call. That is the most common reason a customer rings, and the business cannot currently answer it in software. No agent fix for "have you got it at Campbelltown" can exist until that data does.

Alongside it sit roughly 144 third-party stockists, mostly hardware chains like Mitre 10, Home Hardware, True Value and Autopro, holding stock the business has no visibility into whatsoever. The agent must be able to say "call the store to confirm" without ever implying an availability it cannot verify. A wasted trip is the most expensive failure this system can produce.

Correcting an earlier assumptionThe first version of this architecture called for a fitment graph: make, model, year and variant matched against part. The catalogue says otherwise. Products are named by size and capacity, not by vehicle: 900mm and 1300mm drawers, a 12,000lb winch, 20, 30 and 40 inch lightbars, and one roof rack sold as a "Universal Ute Tub Rack". No vehicle data appears anywhere, and bull bars and suspension are not listed at all. There is no fitment matrix to buy or build.

The question does not disappear, it changes shape. "Will this fit my ute" becomes a constraint problem: whether 900mm drawers suit this tub, which varies by cab configuration, and whether a hard lid or canopy is fitted. Whether a roof top tent's weight sits under this vehicle's roof load rating, and whether cross bars are needed. Whether a lightbar of this width fouls this nudge bar. That is harder to build than a lookup table, and correspondingly harder for anyone else to copy.

Behaviour

Three requests, traced

The same platform, three very different contracts. Watch where the human stays in the loop, and where the agent is allowed to commit.

Call centre: "Will the 900mm drawers fit my dual-cab Hilux, and have you got them at Campbelltown?"

The hardest of the three. The caller expects an answer before they finish the question, and the two halves of that sentence need completely different systems.

  1. Channel
    Caller speaksStreaming STT emits partial hypotheses while the caller is still talking. "900mm drawers" and "dual-cab Hilux" arrive before the sentence ends.
  2. Platform
    Speculative prefetch fires on the partialThe router reads the partial and starts product.get and the vehicle lookup before the caller stops speaking. This is the single biggest latency win in the design.
  3. Platform
    The vehicle question is a constraint problem, not a lookupThere is no fitment matrix. A drawer labelled 900mm is universal-fit, and whether it suits this ute depends on tub length, which differs between single-cab, extra-cab and dual-cab, and on whether a hard lid or canopy is fitted. The agent asks the one detail that changes the answer rather than guessing at it.
  4. Platform
    Stock is asked of the store, not the warehouseinventory.bySku gives the national position. stock.companyStore gives Campbelltown. Where that data does not exist yet, the agent says so and offers a transfer or Click & Collect instead of implying a shelf it cannot see.
  5. Platform
    Guardrail checks the answer before it is spokenEvery price and stock figure must carry a citation from a tool response. An unsourced number is dropped, not softened.
  6. Human
    Escalation stays cheapBelow threshold, on complaint language, or when the caller asks to speak to the store, the call transfers with a generated summary so nobody repeats themselves.

In-store: "Customer wants a refund on a winch bought fourteen months ago, and the receipt is gone."

A policy question disguised as a product question, and the clearest argument in this document for keeping a human on the commit.

  1. Channel
    Staff member asks inside the POSTyped, not spoken. The customer is standing at the counter, so the interaction has a social dimension the agent should not attempt.
  2. Platform
    The policy question is a rules questionChange of mind gives store credit only, within 30 days, with proof of purchase and authorisation obtained before the item comes back. A major fault is a different regime with different remedies. Fourteen months with no receipt decides which regimes remain open, and the rules engine answers that rather than a paragraph of policy text.
  3. Platform
    Context assembled from four sourcestxn.history for the original sale, customer.get for identity and wholesale tier, product.get for whether the item was clearance, factory seconds or Scratch & Dent, and the date-versioned policy rules.
  4. Platform
    Answer returned as a position, with the regime named"Not eligible for change of mind" and "may have a claim under the voluntary 12-month warranty, subject to assessment" are different answers with different next steps. The agent states which one applies and labels the rest a recommendation.
  5. Human
    Staff commit, warranty assessesrefund.propose stages the action. No cash refund is processed in store, and a faulty item is assessed by the warranty department before any claim is finalised. The audit record names the agent, the staff member and the assessor.
  6. Platform
    Degraded path, if there is no WANA small on-premise model answers policy and specification questions from a replicated corpus. Anything needing live data returns "unavailable" rather than a guess. The transaction path never depends on the AI at all.

Storefront: "Will this roof top tent fit my Prado with factory roof rails?"

The only channel where the customer is alone, unsupervised and about to spend money.

  1. Channel
    Shopper asks on the product pageThe SKU being viewed is passed in automatically. The shopper should never have to name the product they are looking at.
  2. Platform
    Vehicle profile pulled from the sessionIf the shopper has registered a vehicle it is reused. If not, the agent asks for the minimum it needs and offers to save it for next time.
  3. Platform
    The answer is a load calculation, not a compatibility flagThe tent's weight against this vehicle's roof load rating, whether factory rails are present, and whether a cross bar kit is required. The reply names the tent, the cross bars it needs, and the rating it has to stay under.
  4. Platform
    Alternatives are offered, not withheldIf the rating is insufficient the agent names what does fit, rather than leaving the shopper at a dead end with a "no".
  5. Human
    Low-confidence answers route to a personWith the vehicle, the SKU and the reason for uncertainty already attached to the enquiry, so the customer waits for an expert instead of receiving a plausible invention.

The voice latency budget

A caller tolerates roughly a second of silence before they assume the line has dropped. That second has to cover telephony, speech recognition, turn detection, retrieval, model reasoning, speech synthesis and playback. There is no way to spend it sequentially, so the design buys time by starting work before the caller stops speaking.

  • 01Speculate during speech.Start tool calls on the partial transcript. Abandon them cheaply if the finished sentence contradicts the hypothesis.
  • 02Two model tiers on the critical path.The fast model answers routine turns outright. Only hard turns escalate to the frontier model, and only after a filler has been played.
  • 03Endpointing beats silence timers.Semantic turn detection removes roughly 400 ms of dead air compared with waiting for a fixed pause.
  • 04Keep connections warm.Pre-established model and speech sessions. A cold TLS handshake at turn one is a second of silence by itself.
  • 05Barge-in is mandatory.The caller must be able to interrupt. A voice agent that talks over people is worse than an IVR menu.

Sourcing

Build or buy

The brief asks for expertise on platforms and an ability to build where a platform falls short. The line runs in a consistent place: buy the commodity intelligence, build the connective tissue and the domain knowledge. Models, speech and vector search are improving faster than any internal team can, so owning them is a liability. The tool mesh, the vehicle configuration model and the eval suite are specific to this business, so renting them is a liability.

The trap in "buy"A bought platform is only safe if the thing you actually depend on stays yours. Buy the speech engine, but keep the tool mesh, the prompts and the eval suite inside the platform. Otherwise the day the vendor changes pricing or gets acquired, the migration is not a re-integration, it is a rebuild.

Delivery

Six phases, twelve months

Sequence matters more than speed here. Each phase leaves behind a platform capability that the next phase consumes, and the riskiest channel is deliberately not first. Voice is the highest-value and highest-risk build, so it lands after the platform spine has been proven on an audience that cannot generate a viral complaint.

Plane 1

Governance, risk and compliance

Australia has unusually specific obligations for exactly the things this platform does. An AI voice agent that calls customers is telemarketing. A hallucinated price is a misrepresentation under consumer law. An AI that decides a refund is an automated decision with privacy consequences. These are design inputs, not a review at the end.

Privacy Act & the APPs

Call recordings and transcripts are personal information. Cross-border disclosure rules apply the moment a prompt reaches an offshore endpoint, so residency routing is a control, not a preference. Notifiable breaches run through the OAIC.

Automated decision-making

Recent reforms tighten obligations where a computer program makes a decision that significantly affects an individual. Refund approval and warranty denial sit squarely in scope. The design keeps humans on consequential decisions and logs the model's recommendation alongside the human's.

Telemarketing & AI disclosure

Outbound AI calls are telemarketing. Consent must be captured, the Do Not Call Register must be washed, and the agent must disclose that it is an AI. Spoofing a human agent is prohibited and also a brand decision no one should want.

PCI DSS v4.0

The moment a card number enters a voice or chat context, that whole system inherits cardholder-data scope. The design never lets it happen: payment links, DTMF masking at the carrier, and transcript redaction as a hard output filter.

Consumer law grounding

Misleading conduct applies to machine statements. An invented stock level or fitment claim is a misrepresentation whether or not a human typed it. Groundedness is therefore a legal control with an eval threshold, not a quality nicety.

Residency & vendor assessment

Personal data and transcripts stay in an Australian region wherever the provider offers one. Where it does not, the disclosure is documented and assessed rather than assumed away.

Retention and erasure

A retention schedule for transcripts, and a working erasure path that reaches the vector index. Embeddings of personal data are still personal data, and this is the step most teams discover they cannot perform.

Kill switch & audit lineage

Per-agent and per-channel stop control with a tested runbook. Every call traceable to the model version, prompt version, tool versions and retrieved documents that produced it.

Risk tiering drives everything elseEvery use case is classified before it is built: L1 advises a human, L2 acts but requires approval, L3 acts autonomously within limits. The tier sets the eval threshold, the logging depth, the human-in-the-loop requirement and the blast radius. Nothing is promoted to L3 by enthusiasm; it is promoted by evidence from a shadow run.

Decision records

The calls that shape everything else

Each of these is expensive to reverse. They are recorded with the trade-off that was accepted, because the alternatives are reasonable and will be raised again.

ADR-001

MCP servers are the only path from agent to system of record

Context
Nineteen systems, three channels, and a team of fifteen. Direct API calls from each agent would produce three parallel integrations per system and no shared contract.
Decision
One typed MCP server per system, owned by the platform team, versioned and eval-covered like any other service.
Trade-off
An extra hop and a schema to maintain. In exchange, no agent holds credentials, no agent knows an endpoint, and a system can be replaced without touching a prompt.
ADR-002

No channel calls a model provider directly

Context
Model prices, capabilities and regional availability change on a monthly cadence. Three channels calling three SDKs makes every change a three-way migration.
Decision
All inference through one gateway that owns routing, fallback, caching, budget caps and per-cost-centre accounting.
Trade-off
The gateway can lag a provider's newest feature by days, and becomes a shared dependency that must never be down. Accepted, because provider lock-in across three channels is the larger risk.
ADR-003

The POS keeps working with no network, and the AI is not on its critical path

Context
Stores lose connectivity. A cloud-only assistant turns a WAN outage into a queue at the counter.
Decision
A small on-premise model answers policy and fitment from a replicated corpus. Anything needing live data returns unavailable rather than a guess. The transaction path never depends on inference at all.
Trade-off
A second deployment target, a replication pipeline, and a capability that differs from the cloud path. Accepted, because a checkout that stops is unrecoverable and an assistant that degrades is not.
ADR-004

Buy voice orchestration, build the tool layer

Context
Real-time audio transport, jitter handling and interruption logic are genuinely hard and genuinely solved by vendors. Tool integration into this business is neither solved nor for sale.
Decision
Start on a voice platform for the realtime leg. Keep the tool mesh, prompts and evals in the platform from day one, behind an interface thin enough to swap the orchestration layer.
Trade-off
A vendor sits on the critical path for the highest-value channel. Mitigated by keeping the replaceable part small and the owned part large.
ADR-005

No prompt reaches production without a passing eval delta

Context
Prompts are edited in dashboards, by many people, with no review and no history. A single word change can alter refund behaviour across three channels.
Decision
Prompts and agent configurations live in git beside the code they drive. CI scores every change against golden datasets and refuses regressions.
Trade-off
Slower iteration and real work to build the datasets. Accepted, because unreviewed prompt changes are the most common way an AI system degrades without anyone noticing.
ADR-006

Personal data is routed to Australian regions by default

Context
Transcripts, customer records and vehicle details flow through every inference call. Offshore endpoints are cheaper and sometimes faster.
Decision
The gateway classifies the payload and routes anything carrying personal information to an Australian region, accepting a cost and capability penalty where one exists.
Trade-off
Some models arrive later in Australian regions, and a few not at all. Accepted, because cross-border disclosure of call recordings is a compliance exposure that does not reduce over time.
ADR-007

Humans commit every money-moving action

Context
Refunds, credits, discounts and warranty outcomes are exactly where an AI error is most expensive and most visible.
Decision
Agents gather, reason and propose. A human commits. Both are named in the audit record. Promotion to autonomous commit requires a shadow run and an explicit risk-tier review.
Trade-off
The labour saving is smaller than the demo implies. Accepted, because a single mis-issued refund to the wrong customer costs more than the efficiency gained.

Operating model

How fifteen people run this

The platform is run as an internal product with a named owner, an SLA and a roadmap, not as a shared library that everyone edits. A platform with no owner becomes a dumping ground within two quarters.

Platform pod · 3–4

Gateway, MCP mesh, retrieval, guardrails, eval harness, observability. Owns the SLAs every channel depends on.

Voice pod · 2–3

Telephony, realtime audio, latency budget, containment quality, compliance of the voice channel.

Commerce & store pod · 2–3

Storefront assistant, POS copilot, offline path, counter workflows.

Data & knowledge · 2

Vehicle configuration model, corpus ownership, data quality, policy rules. Reports to neither channel pod, deliberately.

Platform reliability & security · 2

Egress control, secrets, residency, incident response, the kill-switch runbook.

Product & analysis · 1–2

Use-case intake, risk tiering, before-and-after measurement, the governance forum.

The engineering method is itself a deliverable

The brief asks for someone fluent in AI-first tooling, and that has a concrete architectural consequence: the same discipline applies to the platform's own development. Specifications committed alongside code. Agentic review on every pull request. An internal MCP server for the team's own tooling, so debugging a production conversation is a question rather than a query hunt. Repository-level convention files so every agent working in a codebase inherits the same constraints.

This is not a productivity footnote. A team that uses evaluation gates, versioned prompts and traced failures on its own work finds the same discipline obvious in the platform. A team that does not will ship prompts nobody can audit.
